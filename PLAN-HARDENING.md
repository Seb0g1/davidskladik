# DavidSklad — План устранения ошибок «под ноль» (hardening)

Цель: не «чинить баги по одному», а закрыть **классы** ошибок так, чтобы они физически
не могли повторяться — за счёт инвариантов, тестов, мониторинга и единого дизайна.

## 0. Принцип

Каждая ошибка этой и прошлых сессий принадлежит к повторяющемуся **классу**. Чиним класс,
а не симптом. Для каждого класса: (а) автоматическая защита, (б) тест, который падает при
регрессе, (в) сигнал в мониторинге, если защита всё же пробита в проде.

---

## ЭТАП 1 — Корректность данных (backend)

### 1.1 Инвариант «вычисляемые поля не персистятся / не фильтруются в SQL»
Корень бага мёртвого stock-sweep: SQL фильтровал по `raw->'selectedSupplier'`, которого в БД
никогда нет (поле вычисляется при сборке).
- [ ] Завести явный список **вычисляемых** полей (`selectedSupplier`, `ready`, `nextPrice`,
      `changed`, `priceSource`, `supplierAlternatives`, …) в одном модуле-константе.
- [ ] Линт-проверка (скрипт в CI): grep по `parts/*.js` — любой `raw->'<computed>'` или
      `product.<computed>` в коде, который читает из `productFromPostgres` без пересборки,
      помечается как ошибка.
- [ ] Аудит всех фоновых SQL-свипов (price/stock/zero-stock/reconciler/fast-unarchive) на
      предмет фильтрации по непостоянным полям. Каждый свип обязан резолвить supplier через
      `buildFreshWarehouseProducts`, а не через сырую строку.

### 1.2 Детерминизм цены (закрыть «вечно устаревшие», план C)
- [ ] Детерминированный выбор поставщика: стабильная сортировка с явным тай-брейком по
      `rowId` (уже частично есть) + фиксация курса на момент пересчёта.
- [ ] При записи продукта синхронно проставлять ВСЕ поля цены (`marketplacePrice`,
      `currentPrice`, `nextPrice`, `targetPrice`) из одного источника, чтобы колонки не
      расходились после следующего ребилда.
- [ ] Тест: дважды подряд пересобрать один и тот же продукт без изменений входных данных →
      `nextPrice` обязан совпасть (отлов осцилляции 6708↔7086).
- [ ] Метрика `stalePriceLinked` в дашборд + алерт, если > N в течение часа.

### 1.3 Очереди и приоритеты (отлов «recovery starves price»)
- [ ] Зафиксировать контракт приоритетов в одном месте (enum): price=1–2,
      recovery/unarchive=3–4. Запретить хардкод чисел по коду.
- [ ] Тест: при заполненной очереди price-задачи не должны простаивать дольше T при наличии
      recovery-задач (проверка относительного порядка при concurrency=N).
- [ ] Метрика возраста самой старой price-задачи; алерт при превышении.

### 1.4 Кэш-инварианты (отлов «страница не обновляется после мутации»)
Корень: инвалидация ДО коммита + репопуляция гонкой.
- [ ] Правило: любая мутация склада инвалидирует кэш **после** записи (перед `response.json`),
      а не до. Ввести хелпер `withWarehouseMutation(fn)`, который сам делает финальную
      инвалидацию — запретить ручные вызовы в роутах.
- [ ] Никогда не кэшировать частичные/пустые страницы (уже чинили — закрепить тестом).
- [ ] Тест: сохранить привязку → немедленный GET страницы возвращает товар как linked.

## ЭТАП 2 — Защита процессов (отказоустойчивость)

### 2.1 Watchdog от зависания event-loop
PM2 не перезапускает процесс с запиненным циклом (статус остаётся `online`).
- [ ] Внешний health-watchdog: пинг `/health` обоих портов каждые 30–60с; при N подряд
      таймаутах — `pm2 restart` зависшего процесса + запись инцидента.
- [ ] Liveness-heartbeat: воркер раз в 15с обновляет timestamp; если устарел > 90с — рестарт.
- [ ] Запрет на источник прошлого зависания: лайтовый ESLint-правило/ревью-чеклист против
      `while(regex.exec(...))` без флага `g` (травел-сет инцидент).

### 2.2 Конфигурация одним источником
`ecosystem.config.cjs` молча переопределял `.env`.
- [ ] Один источник правды для env. На старте логировать эффективные значения ключевых
      переменных (concurrency, интервалы свипов, лимиты) — чтобы расхождение было видно сразу.
- [ ] Скрипт-проверка: ключи, заданные и в `.env`, и в `ecosystem.config.cjs`, с разными
      значениями → предупреждение при деплое.

### 2.3 Манифест сборки (`source.js`)
Новый файл-часть легко забыть зарегистрировать → «функция есть, но её нет».
- [ ] Проверка в CI: каждый `server/parts/*.js` присутствует в `source.js` (и наоборот) —
      иначе сборка падает с понятной ошибкой.

### 2.4 Резервные копии БД
- [ ] Ежедневный `pg_dump` с ротацией (7 дней) + проверка восстановления на стейдже раз в неделю.

- [ ] **Юнит-тесты чистых функций**: `roundPrice`, выбор поставщика, `shouldSkipWarehouse…`,

- [ ] **Контрактные тесты маркетплейс-лимитов**: Yandex chats/reviews limit ≤20, Ozon ≤100

- [ ] CI-гейт: тесты + линты (1.1, 2.2, 2.3) обязательны перед merge в `main`.
