Критические проблемы — сломан UX

!
WbPage
UXНезавершено

Страница Wildberries — незавершённая заглушка

Страница WB существует, но значительная часть функционала отсутствует в UI: нет удобного управления карточками, нет фильтров по статусам ошибок, нет детального просмотра per-карточки. Операторы вынуждены смотреть на сырые данные или пользоваться другими страницами.

Что сделать: Полноценный дизайн страницы WB — статусы карточек с цветными бейджами, фильтр по ошибкам, кнопка форс-синка, прогресс загрузки фото.

!
AvitoPageImportPage
UXНезавершено

Страница Avito — грубая структура без полноценного UI

AvitoPage содержит правила фида и коэффициенты цен, но форма настроек незавершена: нет валидации, нет предпросмотра матчинга в живом режиме, нет понятного статуса фида (когда последний раз обновлён, сколько объявлений). ImportPage для Avito — тоже частичная реализация.

Что сделать: Секция статуса фида (дата, кол-во объявлений, ссылка), форма правил с валидацией, живой предпросмотр нескольких товаров по текущим настройкам.

!
SupportChatsPage
UXUI

SupportChats vs Chats — несоответствие стиля и опыта

SupportChatsPage выглядит как отдельное приложение внутри панели: другие цвета кнопок, другая структура, нет общих компонентов с ChatsPage. Оператор, привыкший к Chats, не сразу понимает как работать.

Что сделать: Унифицировать с ChatsPage — вынести общие компоненты (чат-лист, шаблоны, поле ввода) в shared-компоненты. Одинаковый header и layout.

!
ShopAdminPage
UXНезавершено

ShopAdmin — интерфейс магазина не доделан

Баннеры, праздники, категории, правила наценки — часть секций есть, но не все функции доступны через UI. Некоторые настройки требуют прямого редактирования БД.

Что сделать: Завершить UI управления баннерами (загрузка фото, порядок), категориями (дерево), праздничным расписанием (календарь).

Средние проблемы — мешают работе

2
DashboardStatistics
UX

Dashboard и Statistics — дублирование данных, нет чёткого разделения

Dashboard показывает метрики продаж, финансы, поставщиков, очередь операций — и Statistics тоже показывает активность, финансы, привязки. Пользователь не понимает зачем открывать Statistics если Dashboard уже всё показывает.

Что сделать: Dashboard = живой операционный монитор дня (заказы, сборка, очередь, алерты). Statistics = аналитика за период (по сотрудникам, по маркетплейсам). Убрать дублирующиеся блоки.

2
SettingsPage
UXUI

Settings — хаб из 9 ссылок без навигации внутри

Страница Settings — это просто список ссылок на другие страницы. Нет breadcrumb, нет возможности понять где ты сейчас, нет группировки настроек (маркетплейсы, ценообразование, пользователи). При открытии подстраницы нет способа быстро вернуться к списку.

Что сделать: Сгруппировать настройки в 3-4 категории с вертикальным меню слева (как в современных панелях). Добавить breadcrumb и кнопку «Назад».

2
Suppliers
UXUI

SuppliersPage — самая плотная страница, перегрузка информацией

Страница поставщиков содержит: список, сальдо, артикулы, историю платежей, корзину, диагностику — всё в одном. При открытии поставщика открывается огромный аккордеон со множеством разделов. Новый сотрудник теряется.

Что сделать: Разбить карточку поставщика на вкладки: «Баланс», «Артикулы», «История», «Настройки». Скрыть редкие опции за «Дополнительно».

2
PricesPage
UIPerf

Prices — список из 2000 строк без виртуализации

При 2000 товарах и фильтрах страница рендерит весь список в DOM. С включёнными фильтрами работает быстро, но без фильтрации — тормоза на слабых машинах. Нет группировки по причине (reason) визуально понятной.

Что сделать: Добавить виртуализацию списка (react-virtual уже есть в зависимостях), группировку карточек по reason с заголовками-разделителями.

2
WarehousePage
UI

Warehouse — карточка товара перегружена, сложно найти нужное

Карточка товара в складе открывает 10+ секций (маркетплейсы, цены, привязки, фото, группы, WB, Avito...). Всё показывается сразу. Сотруднику, который просто хочет посмотреть цену — приходится скроллить.

Что сделать: Ввести «режим просмотра» (только ключевая информация) и «режим редактирования» (все секции). Или вкладки в карточке.

2
SystemPage
Функция

System — только текущий снапшот, нет трендов

Страница системы показывает текущее состояние (Redis, Postgres, PM, очереди). Но нет графика: не видно когда были пики нагрузки, не понятно как менялась память за сутки, нет истории рестартов.

Что сделать: Добавить mini-графики (последние 24 часа): heap memory, event loop lag, slow requests/min. Хранить 24h метрик в Redis.

2
ReviewsQuestions
Архитектура

Reviews и Questions — почти идентичные страницы, дублирование кода

ReviewsPage и QuestionsPage имеют одинаковый layout, одинаковые фильтры, одинаковые AI-черновики, одинаковые шаблоны. Логика дублирована. При изменении одной нужно помнить про другую.

Что сделать: Вынести в общий компонент FeedbackPage с параметром mode=reviews/questions. Сэкономит ~400 строк и упростит поддержку.

2
PickingList
UIUX

PickingList — отчёт и список сборки смешаны на одной странице

Страница совмещает: фильтрованный список заказов для сборки, отчёт оплат по сборщикам, баланс сотрудников, историю. Переключение между режимами неочевидно, особенно для новых сотрудников.

Что сделать: Разделить на две под-страницы или добавить чёткие вкладки: «Текущие заказы» / «Отчёт оплат» / «Балансы».

2
DashboardSuppliersPickingList
Perf

Множественные параллельные запросы без скелетонов для всех секций

Dashboard загружает 7+ queries параллельно. Некоторые секции появляются мгновенно, другие «прыгают» когда данные приходят. Визуально страница «скачет» при загрузке.

Что сделать: Добавить Skeleton-заглушки для ВСЕХ секций, которые ждут данных. Зафиксировать высоту блоков во время загрузки чтобы страница не прыгала.

2
Tnved
UIНезавершено

TnvedPage — прогресс назначения кодов незавершён в UI

Страница ТН ВЭД имеет базовую таблицу назначений, но прогресс-бар и dry-run режим реализованы частично. Непонятно сколько товаров ещё без кода, нет сортировки по «срочности».

Что сделать: Добавить сводку прогресса (X из Y с кодом), фильтр «только без кода», кнопку «Назначить всё по категории».

2
All
UX

Sidebar — нет настройки, фиксированный порядок страниц

У каждого сотрудника разные приоритеты. Сборщик всегда идёт на PickingList, менеджер — на Suppliers, администратор — на Dashboard. Сейчас все видят одинаковый список страниц в одном порядке, нельзя ничего перенести или скрыть.

Что сделать: Добавить drag-and-drop настройку sidebar. Каждый пользователь может перетащить нужные страницы наверх и скрыть ненужные. Порядок сохраняется в localStorage или в профиле пользователя на сервере.

Косметика и polish

3
BrandBansBrandsTnvedTnved
UI

Много inline-стилей вместо CSS-классов

BrandBansPage и BrandsTnvedPage используют style={{'{'}}{'{'}} вместо CSS-классов. Это делает UI несоответствующим остальным страницам и усложняет dark/light переключение в будущем.

Что сделать: Перенести повторяющиеся inline-стили в styles.css классы.

3
All
UI

Нет анимаций перехода между страницами

Переход между страницами мгновенный (hard flash). Современные панели используют лёгкий fade-in для страниц. Уже подключён TailwindCSS с transition-утилитами.

Что сделать: Добавить opacity-0 → opacity-100 transition при монтировании страниц (100ms). Опционально — slide-in для модалок.

3
Statistics
UI

Удалённые пользователи не визуально отличаются

В Statistics удалённые сотрудники показываются с маленькой пометкой. При беглом взгляде непонятно кто активен, кто нет.

Что сделать: Зачёркнутый текст + серый цвет + opacity-60 для удалённых. Добавить toggle «показать удалённых» (по умолчанию скрыть).

3
ChatsPickingList
UX

Нет индикатора несохранённых изменений

На страницах с формами (Chats черновики, PickingList оплата) пользователь может случайно закрыть вкладку потеряв введённый текст. Нет предупреждения.

Что сделать: Добавить beforeunload warning когда есть несохранённые данные в форме.

3
System
UI

Аббревиатуры в системной таблице без подсказок

System-страница показывает названия компонентов сокращённо. Без знания кода непонятно что означает pg_upsert_call или reconciler_recovery.

Что сделать: Добавить tooltip при наведении с описанием каждого компонента.

3
RecoveryQueueNoSupplier
UI

Поиск без debounce на медленных страницах

Поле поиска на RecoveryQueuePage и NoSupplierPage фильтрует при каждом нажатии клавиши. На больших списках это вызывает лаги.

Что сделать: Добавить useDebounce(300ms) на все поля поиска которые фильтруют большие списки.

3
AvitoWB
UI

Поля цен без указания единиц (₽ или $)

На страницах Avito и WB поля ввода для цен и коэффициентов не имеют подписи единиц. Неясно — вводить рубли, доллары или коэффициент.

Что сделать: Добавить suffix/prefix к каждому полю: ₽, $, ×.

All
UI

Нет единого компонента пустого состояния (empty state)

Когда список пустой (нет товаров, нет заказов) — разные страницы показывают разный текст или вообще ничего. Нет иконки, нет подсказки что делать.

Что сделать: Создать компонент EmptyState с иконкой и текстом. Применить на всех страницах где список может быть пустым.

Новые функции

N
НовоеФункция

Настраиваемый sidebar — drag-and-drop порядок страниц для каждого пользователя

Запрос от пользователя: каждый сотрудник должен иметь возможность настроить sidebar под себя — перетащить нужные страницы наверх, скрыть ненужные.

Реализация:

1. Кнопка «Настроить» в footer sidebar (шестерёнка). Открывает модалку со списком страниц.

2. Drag-and-drop порядка (библиотека @dnd-kit/core — уже используется в проекте или лёгкая).

3. Чекбокс «скрыть» для каждой страницы. Скрытые уходят в «Ещё» в нижней части sidebar.

4. Сохранение в localStorage (быстро) + синхронизация в профиль пользователя на сервере (опционально).

5. Кнопка «Сбросить» для возврата к дефолту.

N
НовоеФункция

Уведомления о событиях прямо в панели (in-app notifications)

Сейчас события (отмена заказа, ошибка цены, новый отзыв) приходят только в Telegram. Нет способа увидеть их прямо в панели без переключения на Telegram.

Реализация: Колокольчик в header с числом непрочитанных. Pull-to-refresh или WebSocket. Уже есть Web Push (VAPID ключи) — можно использовать его API.

N
НовоеФункция

Light mode / Dark mode переключатель

Сейчас панель только тёмная. Некоторым сотрудникам в светлом офисе удобнее светлая тема. CSS уже структурирован с CSS-переменными, сделать light mode реально без большой работы.

Реализация: Добавить [data-theme="light"] класс на body + переопределить CSS-переменные. Тумблер в header или в Settings. Сохранять в localStorage.

Что объединить или убрать

Statistics
Архитектура

StatisticsPage — кандидат на объединение с Dashboard

80% данных Statistics уже есть на Dashboard. Отдельная страница оправдана только если там будет глубокая аналитика по сотрудникам. Сейчас она выглядит как недодобавленный раздел Dashboard.

Предложение: Перенести статистику сотрудников во вкладку на Dashboard. Страницу Statistics убрать из sidebar (оставить роут для прямых ссылок).

?
ReviewsQuestions
Архитектура

Reviews и Questions — объединить в одну страницу «Обратная связь»

Страницы идентичны по структуре. Оператор обрабатывает и отзывы, и вопросы в одном потоке. Нет смысла переключаться между двумя страницами.

Предложение: Одна страница «Обратная связь» с вкладками «Отзывы / Вопросы» или единым смешанным списком с фильтром по типу.

?
Sidebar
Архитектура

Слишком много пунктов в sidebar — реорганизация нужна

Сейчас в sidebar 20+ пунктов — слишком много для быстрой навигации. Часть страниц (BrandBans, BrandsTnved, Tnved, RecoveryQueue, NoSupplier) используются редко и захламляют меню.

Предложение: Сгруппировать редко используемые страницы в раздел «Инструменты» или «Диагностика» с раскрывающейся группой в sidebar. До внедрения drag-and-drop (см. выше) — хотя бы визуальные разделители.
