Баги

Поведение, которое либо некорректно, либо вводит пользователя в заблуждение.

# Тип Приор. Объём Описание
1 Баг P0 XS
Поле «Наличные сейчас» не обрабатывает запятую
Поле суммы оплаты поставщику (верхний инпут в карточке поставщика) передаётся через Number(draftAmount) без замены , → .. Пользователи с RU-раскладкой часто вводят «1,5» вместо «1.5» — получают NaN, кнопка «Заплатил» остаётся задизейблена, без объяснения причины.
PickingListPage.tsx:1045
Фикс: Number(String(draftAmount).replace(",", ".")) перед мутацией.
2 Баг P0 XS
Balance-панель не закрывается кликом вне её
balancePanelOpen открывается по клику на чип, но нет click-outside обработчика. Закрыть можно только повторным кликом на тот же чип. На мобильном это неудобно — пользователь случайно открывает панель и не понимает как скрыть.
PickingListPage.tsx:470–479
Фикс: useClickOutside-ref на панели, или backdrop-overlay как у PM-поиска.
3 Баг P1 XS
Неверная иконка «Редактировать» в истории выдач
Кнопка редактирования записи о выдаче денег использует иконку <Clock size={11} />, которая семантически означает «история» или «время». Пользователь-нетехнарь не может угадать, что это редактирование.
PickingListPage.tsx:688–696
Фикс: заменить на Pencil из lucide-react.
4 Баг P1 XS
Одинаковые иконки у «Возврат» и «К сборке» в статусе picked
Обе кнопки используют <RotateCcw size={14} />. Пользователь не различает их визуально. «Возврат» означает возврат товара клиентом; «К сборке» — откат статуса пикинга. Это разные операции с разными последствиями.
PickingListPage.tsx:1256–1263
Фикс: «Возврат» → PackageX или ArrowLeftRight, «К сборке» оставить RotateCcw.
5 Баг P1 S
Отложенные позиции (deferredUntil) видны дважды на странице
Отложенные строки (с deferredUntil > now) попадают одновременно в блок «На ближайшие дни» и в группы поставщиков ниже (т.к. их статус open). Сборщик видит товар в списке и путается — надо его брать сегодня или нет?
PickingListPage.tsx:361–384 / grouped useMemo
Фикс: исключить строки с активным deferredUntil из grouped, показывать только в календарном блоке.
6 Баг P1 XS
Нет обработчика Escape для модала «Не было»
Модал с выбором срока отсутствия товара не реагирует на нажатие Esc. Все остальные модалы в системе закрываются по Escape (PM-поиск, etc). Непоследовательность в UX.
PickingListPage.tsx:1366–1410
Фикс: добавить useEffect с keydown listener при missingRow !== null.
7 Баг P2 XS
pickQtyDrafts не сбрасываются при смене фильтра
Частичный ввод количества сборки сохраняется в pickQtyDrafts, но не очищается при смене статуса или поставщика в фильтре. При возврате к тому же товару в другом фильтре черновик остаётся — риск случайной неверной сборки.
PickingListPage.tsx:169, строки управления фильтром 778–807
8 Баг P2 XS
Переменная balance (ledger) вычисляется, но нигде не отображается
На строке 986 вычисляется const balance = Number(ledger.balance || 0), но в JSX эта переменная не используется. Актуальный знак баланса (долг vs. аванс) не сигнализируется пользователю цветом или индикатором — потеря информации.
PickingListPage.tsx:986–989

Мобильный

Страница активно используется со смартфона (сборщик в пути). Найденные проблемы снижают скорость работы.

# Тип Приор. Объём Описание
9 Mobile P0 S
«Наличные сейчас» + «Комментарий» + «Заплатил» не помещаются в строку на ≤ 390px
supplier-payment-row использует flexbox без явного мобильного стека. На iPhone SE / Galaxy A-серии все три элемента пытаются уместиться в одну строку → кнопка «Заплатил» обрезается или совсем уходит за край. Инпут суммы сжимается до ~60px и неудобен для ввода.
PickingListPage.tsx:1026–1049 / styles.css:supplier-payment-row
Фикс: на max-width: 480px — stack column, кнопка на всю ширину.
10 Mobile P0 XS
Balance-панель не скроллируется, переполняет viewport
Панель баланса (picker-balance-panel) не имеет max-height и overflow-y: auto. У администратора с несколькими сборщиками панель (список чипов + форма выдачи + история выдач + возврат + дневной итог) занимает больше высоты экрана → нижняя часть недоступна без прокрутки страницы, при этом фиксированный хедер перекрывает её верх.
styles.css:8736–8750
Фикс: max-height: 85dvh; overflow-y: auto на .picker-balance-panel.
11 Mobile P1 XS
Цена товара (picking-row-price) скрыта на мобильных
CSS-правило .picking-row-price { display: none; } в мобильном breakpoint полностью скрывает цену в заголовке строки. Сборщик не видит, сколько стоит позиция, не разворачивая карточку. Если цена важна для решения «брать или нет», он вынужден делать лишний tap.
styles.css:9420
Фикс: сохранить цену, но скрыть только рублёвый эквивалент (.picking-row-price-rub).
12 Mobile P1 S
Кнопки действий («Не было», «Замена», «Завтра», «Удалить») слишком мелкие и плотные
Вторичные действия в picking-actions получают минимальную высоту из grid, но на мобильных с 4–5 кнопками строка переполняется. Кнопки занимают около 36px высоты при минимальной касаемой зоне 44px (HIG). Риск промаха — нажал «Удалить» вместо «Завтра».
styles.css:9436–9451
Фикс: второстепенные действия свернуть в меню "⋮" (три точки) с bottom sheet на mobile.
13 Mobile P2 S
Три фильтра (Статус / Поставщик / Поиск) занимают много места
На мобильных три label + select/input стекаются вертикально и занимают ~180px до начала списка. В сочетании с хедером, табами и счётчиками → пользователь видит всего 1–2 строки без скролла. Поле «Поиск» особенно редко используется сборщиком на ходу.
PickingListPage.tsx:777–807 / styles.css:8983
Фикс: на mobile — строка с chips статуса (open / picked / all) + кнопка «Фильтры» для остального.
14 Mobile P2 XS
Подзаголовок строки (marketplace / orderId) скрыт на мобильных
.picking-row-sub { display: none; } в мобильном breakpoint убирает информацию о маркетплейсе и номере заказа. Для экспресс-заказов (Zap-бейдж) это ок, но для WB-supply пользователь не видит wbSupplyId без раскрытия.
styles.css:9424
Фикс: показывать marketplace-иконку (буква/цвет) вместо текста — экономия места без потери смысла.

Дизайн / UX

Интерфейс работоспособен, но ряд паттернов создаёт лишние когнитивные усилия при каждодневном использовании.

# Тип Приор. Объём Описание
15 Дизайн P1 S
Кнопка «Все собрал» конкурирует с кликом для раскрытия группы
В сгруппированном заголовке (picking-group-header) клик по всей строке сворачивает/разворачивает группу, а кнопка «Все собрал» вложена в ту же зону через e.stopPropagation(). На мобильном промах на кнопку → сворачивается группа. Промах на заголовок в зоне кнопки → срабатывает «Все собрал» нечаянно.
PickingListPage.tsx:1076–1113
Фикс: вынести «Все собрал» из clickable-зоны заголовка — поместить в отдельный блок после заголовка.
16 Дизайн P1 XS
Стат-блок (К сборке / Собрано / Не было) не интерактивен
Четыре Stat-карточки показывают счётчики, но не кликабельны. Нажать «8 — К сборке» для установки фильтра status=open — ожидаемое поведение, которого нет.
PickingListPage.tsx:770–775
Фикс: обернуть в кнопки с onClick={() => setStatus("open")} и подсветкой активного.
17 Дизайн P1 S
Нет визуального акцента на экспресс-заказах
Экспресс-заказы (с isExpress: true или orderCutoffTime) имеют только небольшой жёлтый Zap-значок в заголовке строки. Карточка поставщика и сама строка никак не выделены. Сборщик может пропустить экспресс-позицию в длинном списке, нарушив дедлайн.
PickingListPage.tsx:1142 / styles.css:9055–9065
Фикс: левая жёлтая граница на строке + плашка с временем дедлайна поверх кнопок, если cutoffTime близко.
18 Дизайн P1 XS
Hint «Долг фиксируется автоматически…» показывается всегда
Под полем «Наличные сейчас» постоянно написан подсказочный текст. При большом числе поставщиков это создаёт шум — опытный пользователь давно знает это правило. Текст занимает место и снижает плотность списка.
PickingListPage.tsx:1050–1052
Фикс: показывать hint только при фокусе на поле, или убрать в тултип иконки «?».
19 Дизайн P2 XS
«Как работает сборка — справка» выглядит как обычный текст
Элемент <details> со справкой стилизован только через inline CSS и выглядит как небрендовый текст. Стрелка браузера по умолчанию не соответствует остальному дизайну.
PickingListPage.tsx:809–822
Фикс: заменить на нативный Collapsible-компонент с ChevronDown, как у других раскрываемых секций.
20 Дизайн P2 S
Отложенные чипы («На ближайшие дни») не кликабельны
Блок с датами отложенных позиций информирует, но не позволяет быстро отфильтровать по конкретной дате. Клик по чипу «Завтра: 3 поз.» должен фильтровать список — сейчас пользователь видит только общий счётчик.
PickingListPage.tsx:896–906
21 Дизайн P2 XS
Строка «Перекупщик» (reseller) не привлекает внимания
Флаг reseller показывается только в раскрытой секции meta как tone-warn-текст. Сборщик, не раскрывший строку, не узнает о рисках.
PickingListPage.tsx:1163–1165
Фикс: добавить иконку-предупреждение рядом с именем поставщика если у него reseller=true.
22 Дизайн P3 M
Balance-панель — inline-дровер вместо bottom sheet
На десктопе панель баланса открывается прямо под кнопкой и выглядит нормально. На мобильном она появляется в потоке страницы и требует скрола вниз для доступа к нижним элементам. Bottom-sheet (sliding up from bottom) — стандартный мобильный паттерн для таких панелей.
PickingListPage.tsx:497–759

Функционал

Идеи, которые расширяют возможности страницы без изменения текущей логики.

# Тип Приор. Объём Описание
23 Фича P1 S
Индикатор «кто что собирает» на уровне поставщика
Сейчас показываются только имена других просматривающих (chip в хедере). Непонятно, кто уже взял карточку поставщика «Алекс» и работает с ней. При двух сборщиках возможны конфликты.
Идея: при клике «Собрал» записывать pickedBy немедленно в локальный state и транслировать через heartbeat-endpoint. На карточке поставщика показывать аватар сборщика который последним трогал её позиции.
24 Фича P1 S
Предупреждение при приближении к дедлайну экспресс-заказа
Поле orderCutoffTime есть в данных, но используется только в раскрытом meta. Если текущее время больше cutoffTime − 30 минут — нужен визуальный алёрт прямо в строке.
PickingListPage.tsx:1163
Идея: badge с обратным отсчётом «Осталось 23 мин» красным цветом рядом с express-иконкой.
25 Фича P2 S
Звуковое / вибро-подтверждение «Собрал»
На мобильном сборщик часто смотрит на товар, а не на экран при нажатии кнопки. Короткая вибрация (navigator.vibrate(80)) или звуковой тик подтвердят действие без визуального контроля. Реализуется без серверных изменений.
26 Фича P2 M
Лимит 500 строк без явного индикатора
Запрос к API делается с limit: "500", но при переполнении пользователь не видит никакого предупреждения. Накладная секция аналогично ограничена 80 строками и лишь тогда показывает inline-warning.
PickingListPage.tsx:101 / 1345
Идея: если rows.length === 500 — показать banner «Показаны первые 500 позиций. Уточните фильтр.»
27 Фича P3 L
QR / штрихкод-сканер для поиска товара в листе
На складе у товара может быть штрихкод. Нажатие иконки-камеры в поле поиска открывает BarcodeDetector (Web API) или quagga2, сканирует оффер-id и сразу фильтрует список. Полезно при большом ассортименте.
