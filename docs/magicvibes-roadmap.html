Блок 1 — Критические проблемы (блокируют продажи)

1
Неправильная цена в каталоге
Критично
Диагноз

Цена на сайте считается по формуле: цена_USD × курс_USD/RUB × коэффициент. Цена_USD берётся из снапшота PriceMaster (MySQL), курс кэшируется 6 ч из внешнего API. Если цена_USD не найдена по артикулу — подставляется currentPrice из склада (цена маркетплейса в рублях, без пересчёта коэффициентом). Это главная причина «неправильных» цен: у товара нет привязки в PM, или снапшот устарел.

Пошаговое устранение
  1. В панели davidsklad.ru зайти в Склад → карточка товара и убедиться, что у товара есть активная привязка к строке PriceMaster (зелёная иконка).
  2. Проверить снапшот: GET /api/warehouse/pm-snapshot/status — дата последнего обновления не должна быть старше 15 мин.
  3. Проверить коэффициент магазина: Настройки → Shop → «Наценка магазина» (по умолчанию 2.2 = 120% наценки).
  4. Если у товара несколько диапазонов USD — правила наценки (markupRules) могут выбрать не тот коэффициент. Убедиться что диапазоны настроены правильно (от minUsd).
  5. Текущий курс: GET /api/usd-rate — убедиться что курс актуален (не задержался в кэше).
Файл: server/parts/02d-shop-api-routes.js:159
Трудозатраты: 1–2 часа (диагностика + настройка)
2
Не отображается остаток на товар
Критично
Диагноз

Сайт берёт остаток из поля targetStock таблицы WarehouseProduct. Поле показывает желаемый остаток на маркетплейсе, а не фактические штуки на полке. Если у товара targetStock = 0 или null — сайт пишет «нет в наличии». Логика «inStock» в коде: stockQty > 0 OR (статус не archived AND цена > 0) — то есть без targetStock товар показывается как «в наличии» без числа.

Пошаговое устранение
  1. В панели davidsklad.ru → Склад: для нужных товаров убедиться, что targetStock ≥ 1 (обычно 5 для привязанных).
  2. Если нужно отображать реальный физический остаток — необходима доработка: добавить поле physicalStock и синхронизировать его вручную через CSV или форму в карточке товара.
  3. Временный фикс (без кода): в настройках магазина отображать «В наличии» / «Нет» вместо числа — это уже работает при любом targetStock > 0.
Важно: targetStock — не физический остаток, а лимит для маркетплейса. Для интернет-магазина правильнее хранить и показывать физические штуки. Это отдельная задача разработки (~4–6 ч).
Файл: server/parts/02d-shop-api-routes.js:283
Трудозатраты: 30 мин (настройка) или 4–6 ч (доработка физического остатка)

Блок 2 — Контентные проблемы

3
Нет отзывов Ozon на карточке товара
Высокий
Диагноз

Рейтинг Ozon синхронизируется через Premium API Ozon (/v1/review/statistic/list) раз в 6 часов и пишется в поле marketplaceState.ozonRating каждого товара. Если синхронизация не запустилась — поле пустое, сайт показывает 0 звёзд. Возможные причины: Ozon Premium API не подключён к кабинету, воркер не запущен (BACKGROUND_JOBS_ENABLED=true не установлен), или у товаров нет productId.

Как проверить и исправить
  1. На сервере: pm2 logs davidsklad-worker | grep "rating sync" — посмотреть есть ли строки «ozon rating sync: updated» каждые 6 ч. Если строк нет или есть «API unavailable» — Premium API не доступен.
  2. Зайти в личный кабинет Ozon Seller → Аналитика → API → Права доступа — убедиться что скоуп statistic или review разрешён.
  3. Если Premium API недоступен — обходное решение: показывать текстовые отзывы, которые покупатели оставляют прямо на сайте через форму (ShopReview модель), они уже сохраняются.
Файл: server/parts/02f-shop-ratings-sync.js
Трудозатраты: 1 ч (диагностика + включение Premium API)
4
Добавить блок последних отзывов Ozon/Яндекс на главную
Средний
Текущее состояние

На сайте уже есть система внутренних отзывов (ShopReview) — покупатели пишут отзывы напрямую на magicvibes.ru, они видны на карточке товара. API GET /api/shop/reviews уже отдаёт последние одобренные отзывы. Отзывы с Ozon и Яндекс не импортируются на сайт — они хранятся только в маркетплейсах.

Что нужно сделать

Backend: Написать джоб синхронизации отзывов с Ozon (/v1/review/list) и Яндекс Маркет в таблицу ShopReview с флагом source = "ozon" | "yandex". Запускать 1 раз в сутки. (~4 ч)

Frontend: На главной странице magicvibes.ru добавить секцию «Что говорят покупатели» — горизонтальная прокрутка карточек отзывов с именем автора, звёздами, текстом, иконкой маркетплейса. (~3 ч)

Модерация: В ShopAdminPage добавить вкладку «Отзывы с МП» — утверждать/скрывать перед показом на главной. (~2 ч)

Трудозатраты: ~9 ч (бэкенд + фронт + модерация)
Метки: BackendFrontend

Блок 3 — Технические ошибки

5
Карта выбора ПВЗ пишет «API error key»
Высокий
Диагноз

Карта ПВЗ работает через Ozon Seller API (/v1/delivery/point/list + /v1/delivery/point/info). Для запроса используются стандартные ключи Ozon продавца (OZON_CLIENT_ID / OZON_API_KEY) — те же, что для синхронизации склада. Ошибка «API error key» означает, что ключи либо не прописаны в .env на сервере, либо у ключа недостаточно прав, либо аккаунт не подключён к FBS-доставке Ozon.

Пошаговое устранение
  1. На сервере (root@81.17.154.153): cat /var/www/davidsklad/davidskladik/.env | grep OZON — убедиться что OZON_CLIENT_ID и OZON_API_KEY заданы.
  2. Открыть браузер → DevTools → Network → найти запрос /api/shop/delivery/pvz и посмотреть полный ответ (там будет HTTP-статус от Ozon).
  3. Статус 403 — у ключа нет права на доставку. Ozon Seller: Настройки → API-ключи → убедиться что есть права delivery.
  4. Статус 401 — неверный ключ. Перегенерировать в кабинете Ozon и обновить .env.
  5. Если Ozon FBS не подключён к кабинету — карта ПВЗ работать не будет. Сначала нужно подключить FBS (см. задачу №6).
Файл: server/parts/02d-shop-api-routes.js:842
Трудозатраты: 30 мин (диагностика + обновление ключей)
Метки: OpsAPI

Блок 4 — Доставка Ozon FBS

6
Что нужно для создания доставки через Ozon FBS
Высокий
FBS (Fulfillment by Seller) — полный чеклист подключения
  • Шаг 1 — Склад в кабинете Ozon: Ozon Seller → Настройки → Склады → «Добавить склад» (тип FBS). Заполнить адрес, время работы, схему отгрузки (доставка курьером Ozon или самовывоз в ПВЗ Ozon).
  • Шаг 2 — API-ключ с правами доставки: Ozon Seller → Настройки → API-ключи → создать ключ со скоупами delivery, read:postings, write:postings. Прописать в .env: OZON_CLIENT_ID и OZON_API_KEY.
  • Шаг 3 — Включить FBS в настройках склада (davidsklad): Настройки → Аккаунты → Ozon → включить FBS-режим (переключатель уже есть в интерфейсе).
  • Шаг 4 — Принять заказ: Когда покупатель оформляет заказ на Ozon → статус «Awaiting packaging» → в davidsklad.ru это отображается на странице Финансы/Операции. Необходимо убедиться, что робот забирает заказы через поллер Ozon (файл 02f-notifications-pollers.js).
  • Шаг 5 — Упаковка и отгрузка (через код): Правильный эндпоинт Ozon: POST /v4/posting/fbs/ship (старый /v1/posting/fbs/package удалён Ozon). Код кнопки «Отгрузить» уже есть в проекте — нужно убедиться что он вызывает /v4/posting/fbs/ship.
  • Шаг 6 — Этикетки: После ship вызвать GET /v2/posting/fbs/package-label → скачать PDF и наклеить на посылку.
  • Шаг 7 — Передача в службу доставки: Передать посылку курьеру Ozon или отвезти в ПВЗ Ozon. Акт передачи: POST /v2/posting/fbs/act/create → GET /v2/posting/fbs/act/check-status → GET /v2/posting/fbs/digital-act/get.
Документация на сервере: docs/Ozon Доставка_ подключение...pdf и docs/Документация Ozon Seller API*.html — там подробно описаны шаги 1–7.
Хорошая новость: Код отгрузки через /v4/posting/fbs/ship уже исправлен в проекте (память: ozon-fbs-ship-api.md). ПВЗ-карта тоже уже реализована. Основное что нужно — настроить склад в кабинете Ozon и проверить ключи API.
Трудозатраты: 2–4 ч (настройка Ozon) + 2 ч (тест с реальным заказом)
Метки: OpsAPIBackend

Блок 5 — Платёжная система

7
Отключить тестовую платёжную систему и перейти на боевую
Высокий
Текущее состояние

На сайте реализована оплата через Ozon Pay (эквайринг). API-адрес — payapi.ozon.ru (production URL, не sandbox). Но для работы нужны 3 секретных ключа в .env. Если ключи не прописаны — заказ создаётся без ссылки на оплату (статус pending вместо payment_pending), покупатель видит «оформить заказ» без оплаты.

Что нужно сделать для боевого режима
  1. Подключить Ozon Pay: Ozon Seller → Финансы → Ozon Pay → «Подключить эквайринг». Вам выдадут accessKey, secretKey и notificationSecretKey.
  2. Прописать в .env на сервере:
    OZON_PAY_ACCESS_KEY=<ваш accessKey>
    OZON_PAY_SECRET_KEY=<ваш secretKey>
    OZON_PAY_NOTIFICATION_SECRET=<ваш notificationSecretKey>
  3. Перезапустить API: pm2 restart davidsklad-api
  4. Настроить webhook в Ozon Pay: URL уведомлений = https://davidsklad.ru/api/shop/payment/notification — прописать в личном кабинете Ozon Pay.
  5. Тест: оформить тестовый заказ на magicvibes.ru → убедиться что появляется ссылка на оплату Ozon Pay → оплатить → проверить что статус заказа стал paid в ShopAdminPage.
Если хотите временно убрать оплату (только форма заказа)

В настройках магазина (ShopAdminPage → Настройки → Оплата) — выбрать режим «Оплата при получении». Тогда заказы будут приходить со статусом pending без ссылки на оплату — нужна ручная обработка.

Файл: server/parts/02d-shop-api-routes.js:1005
Трудозатраты: 1 ч (настройка ключей + webhook)
Метки: OpsAPI

Блок 6 — Обработка заказов с magicvibes.ru

8
Как понимать заказы с magicvibes и что настроить до конца
Средний
Жизненный цикл заказа
СтатусЗначениеДействие оператора
pendingЗаказ создан, оплата не настроенаПозвонить/написать покупателю, уточнить оплату
payment_pendingСсылка на оплату отправленаЖдать оплаты (webhook изменит статус)

cancelledОтменёнВозврат денег (вручную через Ozon Pay)
Где смотреть заказы

davidsklad.ru → Магазин (ShopAdminPage) → вкладка «Заказы». Там список всех заказов с фильтрами по статусу, поиском и кнопкой смены статуса.

Что нужно настроить до конца
  • Email-уведомления покупателю: Прописать SMTP в .env: SHOP_SMTP_HOST, SHOP_SMTP_PORT, SHOP_SMTP_USER, SHOP_SMTP_PASS. Тогда при регистрации/покупке покупатель получит письмо с OTP-кодом или подтверждением заказа.
  • Telegram-уведомления оператору: Добавить отправку сообщения в Telegram при новом заказе. Потребует 2–3 часа разработки: новый джоб в 02f-notifications-pollers.js.
  • Контакты магазина: davidsklad.ru → Настройки → Магазин → заполнить телефон, email, дни доставки, сумму бесплатной доставки.
  • Логистика: Выбрать службу доставки (СДЭК, Почта России, Boxberry). Интеграции нет — пока ручная: оператор получает заказ → сам создаёт накладную в системе доставки → вставляет трек-номер в заказ (поле trackingNumber, добавить вручную в DB или через интерфейс).
  • Фискализация: По закону 54-ФЗ нужна онлайн-касса. Ozon Pay поддерживает фискализацию — включить флаг enableFiscalization: true в коде и передать данные чека (ИНН, наименования товаров). Без этого работа юрлица невозможна.
  • Политика возврата и оферта: Разместить на сайте: страница «Оферта», «Политика возврата», «Политика конфиденциальности» — юридическое требование для интернет-магазина.
Трудозатраты: 1 ч (настройка) + 5–8 ч (email + Telegram + фискализация)
Метки: BackendFrontendOps
