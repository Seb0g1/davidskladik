Sorin Яндекс Экспресс: все 561 обновление остатков завершаются ошибкой
Backend: Worker Яндекс Экспресс
Симптом
Лог sorin_express_sync_complete показывает yandexFailed: 561, yandexSent: 0 каждые ~3 минуты. Ни один товар Сорина не получает корректный остаток на Яндекс Экспресс, остатки никогда не обнуляются при деактивации.
Причина
Функция sendYandexStockChunk возвращает ошибку API для всех 561 товаров. Точный код ошибки нужно проверить в логах: pm2 logs davidsklad-worker --lines 100 | grep sorin_express_yandex_stock_failed. Возможные причины: неверный API-ключ, неверный формат запроса для экспресс-склада, товары не найдены по offerId в кампании 216697459.
Файл
server/parts/02f-sorin-express-sync.js:203–214
Исправление
1. Проверить логи: grep sorin_express_yandex_stock_failed /path/to/logs
2. В зависимости от ошибки: исправить API-ключ в SORIN_EXPRESS_YANDEX_API_KEY, или формат тела запроса в sendYandexStockChunk.
3. Убедиться что offerId товаров совпадают с Яндекс-кампанией 216697459 (не с другой кампанией).
Влияние
Яндекс Экспресс никогда не получает правильных остатков от Сорина. При исчезновении товара у Сорина — экспресс продолжает принимать заказы, которые невозможно выполнить.

WarehousePage: карточка товара — поле autoPriceMin/Max молча срезает расчётную цену
WarehousePage Backend
Симптом
Устаревшие поля autoPriceMin / autoPriceMax (из legacy-UI) молча ограничивают итоговую цену. Например, для Kenzo цена пересчитывалась в 490 ₽ вместо корректных ~4900 ₽. В карточке нет никакой индикации о наличии зажима.
Причина
Ценовой движок применяет autoPriceMin/Max к итогу, но в UI карточки эти поля не отображаются и не редактируются. Оператор не знает что цена зажата.
Файл
server/parts/02a-pricing.js (ценовой движок) + frontend/src/routes/WarehousePage.tsx (карточка)
Исправление
1. Добавить в карточку товара отображение priceClampReason с предупреждением (если цена зажата)
2. Добавить кнопку «Сбросить лимиты» для очистки autoPriceMin/Max
3. Или полностью убрать поддержку этих legacy-полей если они больше не нужны.
Страница: WarehousePage

DashboardPage: SVG-график продаж деформируется на нестандартных размерах экрана
DashboardPage
Симптом
Компонент SalesBarChart вычисляет ширину столбца через 540 / days.length — hardcode на 540px контейнер. С preserveAspectRatio="none" полоски растягиваются/сжимаются по горизонтали при любом другом размере.
Причина
SVG строится без учёта реального размера контейнера (ResizeObserver не используется). preserveAspectRatio="none" отключает пропорциональное масштабирование.
Файл
frontend/src/routes/DashboardPage.tsx:20–36
Исправление
Использовать CSS-bar-chart на div+flexbox (надёжнее, responsive), либо добавить useResizeObserver и пересчитывать viewBox по реальной ширине. Убрать preserveAspectRatio="none".

ConsignmentPage: профит-сплит в превью захардкожен 50/50 (не соответствует реальной логике)
ConsignmentPage
Симптом
В превью операции продажи выводится «спонсору X, мне Y» с формулой profit / 2. Если реальный сплит изменился или привязан к конкретной партии — число вводит в заблуждение.

Фронтенд вычисляет предварительный профит как Math.round(profit / 2 * 100) / 100 без учёта реального коэффициента сплита, который может отличаться у разных поставщиков/партий.
Файл
frontend/src/routes/ConsignmentPage.tsx:1187

Либо загружать коэффициент сплита для товара/партии из API, либо убрать детализацию «спонсору/мне» из превью и показывать только итоговый профит. Если 50/50 — единственный вариант в бизнес-логике, добавить пояснение «(50/50)».
