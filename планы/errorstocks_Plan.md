# NoSupplierPage — Plan

## Current State

Страница «Ошибки наличия» показывает товары с привязками, у которых нет активного поставщика или некорректный остаток. Данные приходят из `/api/warehouse/no-supplier` (кэш 2 мин, тяжёлый запрос ~15 с через `buildFreshWarehouseProducts`). Фильтрация по маркетплейсу — клиентская. Ссылка «Открыть» ведёт в карточку товара склада.

## Bugs / Issues Found

- **Фильтр маркетплейса работает некорректно для WB** — строка 13: `a.marketplace === mpFilter`. Поле `marketplace` у WB-товаров в `buildNoSupplierAlerts` может быть `"wb"`, но в `<select>` (строка 35) опция задана как `value="wb"`. Если `buildNoSupplierAlerts` возвращает `marketplace: "wb"` — всё ок. Но если бэкенд возвращает `"wildberries"` или другой вариант, фильтр не срабатывает. Необходимо проверить значение поля в реальных данных.

- **`<select>` не обёрнут в `<label>` и использует нативный стиль inline** — строка 32: нативный `<select>` без className и `aria-label`, тогда как остальные страницы используют компонент `<SelectField>` с унифицированным стилем. Выпадающий список выглядит разнородно.

- **Кнопка «Обновить» не блокируется во время загрузки** — строка 16: `onClick={() => query.refetch()}` — кнопка не имеет `disabled={query.isFetching}`. При двойном клике запрос будет отправлен повторно пока первый ещё выполняется.

- **`data?.withoutSupplier` vs реальное количество в списке** — строка 19: стат «Без поставщика» показывает `data?.withoutSupplier`, а «В списке» — `alerts.length` (после фильтра). Когда выбран конкретный маркетплейс, «Без поставщика» остаётся глобальным числом, а «В списке» — фильтрованным. Это создаёт путаницу: цифры расходятся без объяснения.

- **`(data as Record<string, unknown>)?.cachedAt` — избыточный cast** — строки 23–28: `NoSupplierSchema` в `types.ts` уже должен содержать поле `cachedAt`, но его нет в схеме (фронтенд кастит через `as Record<string, unknown>`). Поле `cachedAt` добавляется бэкендом динамически (строка 273 сервера) и не включено в Zod-схему — отсюда unsafe cast.

- **`a.marketplace` кастится через `(a as Record<string, unknown>).marketplace`** — строка 13: то же самое — поле `marketplace` отсутствует в типе `NoSupplierSchema`. Безопасный вывод типов не работает.

- **Нет индикатора ошибки запроса** — `query.error` нигде не рендерится. Если бэкенд упадёт с ошибкой (например, PM MySQL недоступен), пользователь увидит только пустой список без сообщения.

## Improvement Ideas

- **[HIGH]** Добавить `cachedAt` и `marketplace` в `NoSupplierSchema` в `types.ts` — убрать unsafe cast, получить корректный типобезопасный доступ.

- **[HIGH]** Показать `query.error` — добавить блок `{query.error ? <div className="inline-error">...</div> : null}` как на других страницах.

- **[MEDIUM]** Заменить нативный `<select>` на компонент `<SelectField>` для единообразия стиля.

- **[MEDIUM]** Заблокировать кнопку «Обновить» пока `query.isFetching`, добавить `<Loader2>` индикатор.

- **[MEDIUM]** Разделить статы: при активном фильтре показывать в «Без поставщика» только число для выбранного маркетплейса, или добавить уточнение «(всего)» / «(для {mpFilter})».

- **[LOW]** Добавить поле поиска по артикулу (клиентская фильтрация `alerts`) — при большом количестве товаров без поставщика найти конкретный сложно.

- **[LOW]** Показывать время следующего обновления кэша (текущее время + TTL), а не только `cachedAt` — это даёт понять когда «Обновить» вернёт свежие данные.
