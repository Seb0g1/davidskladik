# AiDraftsPage — Plan

## Current State

Страница отображает два списка: «Кандидаты» (товары с качеством карточки ниже порога) и «Черновики» (уже сгенерированные AI-материалы). Оператор может запустить генерацию текста + 5 фото по каждому кандидату и затем отправить черновик на Яндекс.Маркет. Фильтрация по статусу черновика и порогу качества. Обе секции живут на одной странице.

## Bugs / Issues Found

- **"Отправить" вызывает неверный эндпоинт** — кнопка «Отправить» (строка 93) зовёт `send.mutate(productId)`, что ведёт на `/api/warehouse/products/:id/yandex-quality-draft/send`. Этот роут нигде не зарегистрирован в читаемых файлах бэкенда. В `02d-warehouse-ai-content-routes.js` есть `/:id/ai-content/:draftId/send`, а не `yandex-quality-draft/send`. Отправка с UI, скорее всего, возвращает 404.

- **`hasDraft` всегда может быть `false` из-за несовпадения идентификаторов** — строки 79–82: проверка ищет черновик где `String(dp.id || dp.offerId) === productId` или `String(dp.offerId) === String(product.offerId)`. `productId` это `String(product.id || row.id || "")`, а список черновиков подтягивается по другому запросу. Если у кандидата `id` отсутствует или расходится с `id` товара в черновике (разные объекты из двух запросов), кнопка «Отправить» будет заблокирована навсегда (`title="Сначала сгенерируйте черновик"`).

- **`imageDrafts` не передаётся бэкендом в списке черновиков** — в `02d-warehouse-ai-drafts-list-route.js` (строка 21–38) объект `row` для элементов `imageDrafts` создаётся как `{ type: "image", draft }`, без поля `imageDrafts`. Фронтенд (строка 108) читает `Array.isArray(row.imageDrafts)` и всегда получает пустой массив для image-черновиков. Галерея из 5 фото в карточке черновика никогда не показывается для image-типа.

- **Прогресс-бар захардкожен на 58%** — строка 61: `<span style={{ width: "58%" }} />`. Значение статичное, не меняется в процессе генерации и вводит пользователя в заблуждение.

- **`generate.error` не сбрасывается при повторном запуске** — `useMutation` в TanStack Query не сбрасывает `error` при новом вызове `mutate` (только после `reset()`). Если генерация упала с ошибкой, то при нажатии «Текст + 5 фото» на другой карточке старая ошибка останется на экране рядом с новой pending-операцией.

- **`lastGenerateProductId` устанавливается до завершения мутации** — строка 28–29: `setGeneratingProductId` и `setLastGenerateProductId` обновляются внутри `mutationFn`, до того как запрос завершился. Если пользователь быстро нажмёт «Повторить» (строка 66), `lastGenerateProductId` может указывать на товар, который сейчас ещё обрабатывается.

- **Лимит `300` захардкожен в обоих запросах** — строка 20: `limit=300` в URL кандидатов, строка 14: `const [limit, setLimit] = useState(300)`. Значение лимита в UI (поле «Лимит проверки») влияет только на запрос кандидатов через `candidatesQuery`, но сам URL `/api/warehouse/ai-drafts` также имеет хардкод `limit=300` (строка 20) и не использует state-переменную `limit`.

## Improvement Ideas

- **[HIGH]** Добавить кнопки «Одобрить» / «Отклонить» прямо в карточке черновика — сейчас ни одна из этих операций (роуты `/approve`, `/reject` из `02d-warehouse-ai-content-routes.js`) не доступна с UI страницы. Оператор не может изменить статус черновика без прямого API-вызова.

- **[HIGH]** Показывать текст черновика (name + description + bulletPoints) полностью или в expandable-блоке — сейчас `draft.description` обрезается до 360 символов (строка 125) и нет способа увидеть полный текст для оценки перед отправкой.

- **[MEDIUM]** Объединить два запроса (кандидаты + черновики) в единый polling-цикл или добавить `refetchInterval` — сейчас при завершении генерации оба запроса инвалидируются, но пользователь не видит прогресс между инвалидациями при длинной очереди.

- **[MEDIUM]** Сделать реальный прогресс-бар для генерации — либо отображать «spinner» без прогресса, либо подключить server-sent events/polling на backend для статуса задачи.

- **[MEDIUM]** Добавить счётчик ошибок генерации (сколько упало за сессию) — сейчас показывается только последняя ошибка.

- **[LOW]** Вынести константу `80` (лимит отображения кандидатов, строка 72–75) в переменную или env — сейчас хардкод скрыт в JSX, не очевидно почему 80 а не 100.

- **[LOW]** Добавить пустое состояние для секции «Кандидаты» (аналог строки 131 для черновиков) — сейчас если `candidates.length === 0` и данные уже загружены, секция просто пустая без пояснительного текста.
