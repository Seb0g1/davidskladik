# NewProductsPage (Новые товары) — Plan

## Current State

Страница показывает товары из прайса поставщиков (PM-снапшот), которых ещё нет на маркетплейсах оператора. Исключаются тестеры и отливанты. Функции: поиск по названию/артикулу (через submit-форму), фильтр по поставщику (через sidebar-список), сортировка, статистика (количество, поставщики, диапазон цен, курс USD), карточки товаров с кнопкой «Найти на складе» (навигация через pushState). Данные берутся из `PriceMasterSnapshotItem` и `ProductLink`/`WarehouseProduct` в Postgres.

## Bugs / Issues Found

- **Поиск срабатывает только по Submit, но `supplierFilter` применяется мгновенно** — строки 108–111 (submitSearch) и 174–176 (setSupplierFilter): поиск текста требует нажатия Enter/кнопки, а фильтр поставщика меняет `params` сразу при клике. Это непоследовательное UX: при наборе текста ничего не происходит, при клике по поставщику — запрос уходит немедленно.

- **`bySupplier` в sidebar не обновляется при активном текстовом поиске** — бэкенд (строка 116–122 `02d-new-products.js`): `bySupplier` считается из `filtered` (уже после q-фильтра). Поэтому sidebar показывает только поставщиков, у которых есть результаты по текущему q. Когда пользователь ищет «Dior», поставщики без Dior исчезают из списка — неожиданное поведение, т.к. sidebar воспринимается как статичный список.

- **`supplierOptions` в коде создаётся, но нигде не используется** — строки 103–106: переменная `supplierOptions` формирует массив для select, но в JSX нет `<select>` с этим массивом. Вместо него реализован sidebar-список кнопок. Переменная — мёртвый код.

- **`ProductCard` навигирует через `window.history.pushState + PopStateEvent`** — строки 67–70: вместо использования `react-router`-навигации (или аналога) компонент вручную манипулирует историей браузера и диспатчит `PopStateEvent`. Это хрупко: при изменении роутинга приложения перестанет работать без правок в компоненте. Кроме того, если `popstate` не слушается в нужном месте, клик просто меняет URL без навигации.

- **`priceMin` вычисляется неправильно при активном фильтре поставщика** — бэкенд строка 124–127: `prices` берутся из `filtered` (после q + supplierFilter). Если поставщик выбран, `priceMin/Max` показывают диапазон только по нему, но стат-блок «Диапазон цен» на фронтенде выглядит как глобальная статистика. Не очевидно, что диапазон фильтрованный.

- **`warehouseNormNames` — name-prefix matching может давать ложные срабатывания** — бэкенд строка 71: `wn.startsWith(nameLower) || nameLower.startsWith(wn)`. Если PM-имя `Chanel` (6 символов) → минимум 8 символов (строка 71: `nameLower.length >= 8`), условие не сработает. Но если PM-имя `Chanel No` (9 символов) — совпадёт с любым товаром склада начинающимся на «chanel no», даже если это другой товар. Порог в 8 символов при суффиксе `nameLower.startsWith(wn)` означает совпадение складского имени «chanel no» (8 сим) с PM «chanel no 5 eau de parfum».

- **`cleanText(item.article).toLowerCase()` используется как ключ в `seenArticles`, но в массив `allCandidates` пушится `cleanText(item.article)` (без lowercase)** — бэкенд строки 59–81: `seenArticles.has(article)` где `article = cleanText(...).toLowerCase()`, но в `allCandidates.push` поле `article: cleanText(item.article)` — с оригинальным регистром. Дедупликация работает, но итоговый артикул в ответе может иметь другой регистр, чем ожидает фронтенд при поиске.

- **Лимит 500 захардкожен в `params` (строка 87: `limit: "500"`)** — при этом UI не предоставляет возможности его изменить. Если у поставщика более 500 новых товаров, часть молча обрезается без предупреждения. Поле `shown < total` обрабатывается (строка 247), но пользователь не может запросить больше.

## Improvement Ideas

- **[HIGH]** Убрать `supplierOptions` — мёртвый код (строки 103–106), создаёт путаницу при чтении.

- **[HIGH]** Заменить `window.history.pushState + PopStateEvent` на proper-навигацию через роутер приложения в `ProductCard` — проверить, как организован роутинг (TanStack Router, React Router) и использовать соответствующий `navigate()` или `<Link>`.

- **[MEDIUM]** Добавить дебаунс на текстовый поиск (как в AvitoPage) — убрать форму с кнопкой Submit, заменить на live-поиск с задержкой 400 мс, аналогично фильтру поставщика. Или оставить Submit, но тогда применять `supplierFilter` тоже только по Submit.

- **[MEDIUM]** Добавить явную метку «Диапазон цен по фильтру» в Stat-блок при активном фильтре — или всегда показывать глобальный диапазон отдельно от отфильтрованного.

- **[MEDIUM]** Добавить предупреждение когда `shown < total` прямо в Stat-блок «Новых товаров» (например, `value="500 из 1200"`) — сейчас предупреждение есть только внизу списка и легко пропускается.

- **[MEDIUM]** Добавить `staleTime: 0` или кнопку «Обновить» с явным `query.refetch()` — страница кэшируется на 2 минуты (`staleTime: 2 * 60_000`, строка 95), но данные PM-снапшота могут обновиться в фоне, и оператор не узнает об этом.

- **[LOW]** Пересмотреть порог name-prefix matching на бэкенде — текущий алгоритм `startsWith` даёт ложные исключения. Рассмотреть точное совпадение или Levenshtein-расстояние вместо prefix-check.

- **[LOW]** Sidebar поставщиков обрезается до 30 записей (бэкенд строка 136: `bySupplier.slice(0, 30)`) — добавить «Показать всех» или пагинацию в sidebar, если поставщиков больше 30.
