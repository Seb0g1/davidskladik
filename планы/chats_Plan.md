# ChatsPage — Plan

## Current State

Страница чатов — самый сложный из трёх модулей. Показывает переписку с покупателями на Ozon, Яндекс.Маркете, Wildberries и Avito в едином двухколоночном layout (список чатов + тред). Поддерживает отправку текста и фотографий, шаблоны с подстановкой переменных (`{{name}}`, `{{order}}`, `{{product}}`), лайтбокс для медиа, черновики (сохраняются в `useRef<Map>` на время сессии), авторазметку Markdown (жирный + ссылки). Список чатов обновляется каждые 30 секунд, история — каждые 15 секунд. WB использует глобальный поток событий с кешем на 60 секунд.

## Bugs / Issues Found

- **WB: `unreadOnly` фильтр молча игнорируется**
  Строки 229–230 (`02f-chats-routes.js`): `// unreadOnly у WB не поддержан (API не отдаёт непрочитанность) — не режем список.` — чаты WB всегда включаются в результат, даже когда оператор включил «Только непрочитанные». Frontend не предупреждает об этом. Оператор видит все WB-чаты при включённом фильтре, что вводит в заблуждение.

- **`wbChatEventsCache` — глобальный Map, никогда не чистится по размеру**
  Строка 66 (`02f-chats-routes.js`): `const wbChatEventsCache = new Map()`. Кеш хранит массивы событий (потенциально тысячи строк) на аккаунт. При рестарте worker-процесса кеш сбрасывается, но в рамках одной сессии растёт. Если событий много и кабинетов несколько — утечка памяти аналогична `ozonSkuNameCache`.

- **История WB: сортировка по ISO-строке даёт неправильный порядок если timestamp числовой**
  Строка 471 (`02f-chats-routes.js`): `rows.sort((a, b) => cleanText(a.createdAt).localeCompare(cleanText(b.createdAt)))`. Поле `createdAt` формируется через `wbChatEventTimestamp`, который возвращает либо ISO-строку, либо `cleanText(raw)` (произвольную строку из API). Если WB вернул числовой timestamp без конвертации (ветка `return cleanText(raw)` при `!Number.isFinite(numeric)`), строковое сравнение ISO vs число даёт неправильный порядок.

- **Черновик (`draftRef`) сохраняется бессрочно и не очищается при отправке**
  Строки 303–305 `ChatsPage.tsx`: после успешной отправки `setText("")` — это правильно, но `draftRef.current.set(selected.chatId, "")` не вызывается. При следующем переключении на этот чат `draftRef` вернёт пустую строку, что нейтрально. Но при снятии фокуса **до** отправки (переключение чата) и возврате — черновик восстанавливается корректно. Реальная проблема: `draftRef` хранит черновики для всех когда-либо открытых чатов в памяти, без ограничения числа записей.

- **`pendingImages` — утечка objectURL при смене чата без очистки**
  `ChatsPage.tsx`, строки 289–293: `useEffect` при `unmount` вызывает `revokeObjectURL`, но только для `pendingImages` на момент unmount. Если пользователь загрузил фото в чат A, переключился на чат B (без отправки), pendingImages сбрасываются через `send.onSuccess` — нет. `pendingImages` сохраняются между сменой чатов. ObjectURL-ы не отзываются при смене `selected`, только при unmount компонента или успешной отправке. Нужно: очищать `pendingImages` (и отзывать URL) при изменении `selected?.chatId`.

- **`renderChatMarkdown` использует `re.lastIndex = 0` снаружи цикла строк**
  Строки 70–98 `ChatsPage.tsx`: регулярное выражение `re` объявлено с флагом `g` снаружи функции (`const re = /.../ g`). При разборе нескольких строк `re.lastIndex = 0` сбрасывается в начале каждой строки — это правильно. Но `re` — модульный singleton: если `renderChatMarkdown` вызывается в нескольких местах одновременно (например, в списке сообщений при рендере), `lastIndex` может быть не сброшен. В React 19 Strict Mode двойной рендер мог бы поймать этот баг. Безопаснее создавать новый `RegExp` внутри функции или использовать `matchAll`.

- **Ozon: чтение чата (`/v2/chat/read`) с `Number(lastId) || lastId`**
  Строка 412 (`02f-chats-routes.js`): `from_message_id: Number(lastId) || lastId`. Если `lastId` — числовая строка типа `"123"`, `Number("123")` = 123 (корректно). Но если `lastId` — UUID или не-числовая строка, `Number(lastId)` = NaN, `NaN || lastId` = строка, — API Ozon ждёт число и выбросит ошибку. Ошибка поглощается через `.catch(() => {})`, то есть чат не помечается как прочитанный молча.

- **Yandex: фильтр `unreadOnly` применяется на клиенте, не в запросе к API**
  Строки 204–207 (`02f-chats-routes.js`): для Яндекса после загрузки всех страниц применяется `.filter((chat) => !unreadOnly || chat.unreadCount > 0)`. API Яндекса поддерживает фильтрацию на стороне сервера (`filter_unread` или аналог) — но не используется. При большом числе чатов это означает загрузку всех страниц (до 10 × 20 = 200 чатов) ради фильтрации 2–3.

- **Счётчик `/1000` символов для WB показывается только в поле ввода, но `fullText` на бэкенде режется по `slice(0, 1000)` вместе с imageUrls**
  Строки 480–481 `ChatsPage.tsx` и строка 540 `02f-chats-routes.js`: счётчик `text.length/1000` учитывает только текст, но не URL картинок, которые добавляются к `fullText` на бэкенде через `.join("\n")`. Если отправляется текст + 2 фото, реальный `fullText` длиннее — часть URL может обрезаться.

- **`substituteTemplate` заменяет только `{{name}}`, `{{order}}`, `{{product}}` — нет защиты от спецсимволов в контексте**
  Строки 50–56 `ChatsPage.tsx`: если `context.buyerName` содержит `$` или `\n` — они попадут в строку без экранирования. В данном случае `replace` с callback-функцией не используется — передаётся строка, поэтому `$&`, `$1` и т.п. в значении будут интерпретированы как backreference. Пример: имя покупателя «Иван $& Петров» превратится в «Иван {{name}} Петров» (потому что `$&` = matched string = `{{name}}`).

## Improvement Ideas

- **[HIGH]** Показать предупреждение/тултип в UI когда выбран фильтр «Только непрочитанные» + маркетплейс WB или «Все» — добавить в `warnings` с бэкенда или обработать на фронте: `{unreadOnly && (marketplace === "all" || marketplace === "wb") && <div className="table-note">WB не отдаёт непрочитанность — показаны все WB-чаты</div>}`.

- **[HIGH]** Исправить `substituteTemplate`: использовать callback-функцию в `.replace()` вместо строки-замены, чтобы избежать интерпретации `$&`, `$1` и т.д. в значении.

- **[HIGH]** Очищать `pendingImages` (и отзывать objectURL) при смене `selected?.chatId` — добавить `useEffect([selected?.chatId])` с очисткой.

- **[HIGH]** Исправить `renderChatMarkdown`: вынести `RegExp` внутрь функции или использовать `String.prototype.matchAll` вместо глобального stateful `re` с `re.lastIndex`.

- **[MEDIUM]** Ограничить размер `wbChatEventsCache`: хранить не более N (например, 3) кабинетов, при превышении удалять старейший.

- **[MEDIUM]** Для Yandex при `unreadOnly=true` передавать фильтр в API Яндекса (если поддерживается) вместо клиентской фильтрации — снизит число запросов и трафик.

- **[MEDIUM]** Счётчик символов WB: учитывать длину URL вложений при подсчёте. Или: для WB не добавлять URLs в текст — отправлять только через отдельный механизм (но WB chat API не поддерживает вложения напрямую, так что нужно предупреждение).

- **[MEDIUM]** Добавить `draftRef.current.delete(selected.chatId)` в `send.onSuccess` чтобы явно удалять отправленный черновик.

- **[MEDIUM]** В `ozonChatTitle` добавить отображение `target` (id кабинета) когда несколько Ozon-аккаунтов — иначе оператор не понимает из какого кабинета пришёл чат.

- **[LOW]** Добавить звуковое или браузерное (Notification API) уведомление при появлении новых непрочитанных сообщений — `unreadTotal` уже есть.

- **[LOW]** Infinite scroll или кнопка «Загрузить ещё» для истории чата — сейчас Ozon отдаёт 100 сообщений, Яндекс — 100, этого может не хватать для длинных переписок.

- **[LOW]** Показывать статус доставки заказа (`context.postingNumber`) прямо в шапке треда с кликабельной ссылкой на заказ в системе.
