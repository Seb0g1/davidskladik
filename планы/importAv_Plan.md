# AvitoPage — Plan

## Current State

Страница управляет полным циклом Avito-автозагрузки: настройка правил импорта (фильтры, коэффициенты цен, стоп-слова), предпросмотр, применение импорта (Ozon → Avito-фид), управление объявлениями, ссылки на XML-фид и CSV-остатки, история загрузок Avito, синхронизация цен/остатков, профиль продавца и баланс. Страница очень широкая функционально и имеет несколько независимых панелей.

## Bugs / Issues Found

- **`apiJson` определена локально, дублируя глобальную** — строки 217–226: в файле объявлена своя функция `apiJson`, тогда как в `frontend/src/api.ts` уже есть глобальный `apiJson`. Локальная версия отличается сигнатурой (нет Zod-валидации), что может привести к расхождению поведения при ошибках. При изменении глобального `apiJson` локальная не обновится.

- **`removeListing.mutate(item.adId)` не запрашивает подтверждения** — строка 912: нажатие на кнопку «Убрать из фида» немедленно удаляет объявление без confirm-диалога. Учитывая, что список содержит до 200 записей, случайное удаление очень вероятно.

- **Список объявлений ограничен 200, но `matched` может быть > 200** — строки 887, 924–928: `listings.slice(0, 200)` и проверка `(listingsQuery.data?.matched ?? 0) > listings.length`. Сервер возвращает до 200 элементов в `items`, поэтому `matched > listings.length` никогда не сработает, если сервер уже ограничил выборку — пользователь не увидит предупреждение о неполноте списка.

- **`syncStatus?.feedRefreshRunning` блокирует кнопку «Синхронизировать сейчас», но `syncNow.isPending` не добавляет его в лоадер** — строка 743: условие спиннера `syncNow.isPending || syncStatus?.feedRefreshRunning`, но текст кнопки (строка 744) меняется только при `syncNow.isPending`. При фоновом `feedRefreshRunning` кнопка показывает спиннер, но текст остаётся «Синхронизировать сейчас», что вводит в заблуждение.

- **`triggerUpload` не сбрасывает успех при повторном нажатии** — строка 480: `{triggerUpload.data ? <div ...>Автозагрузка запущена</div> : null}`. TanStack Query не очищает `data` при повторном вызове мутации — если нажать «Запустить автозагрузку» ещё раз, сообщение об успехе останется от предыдущего вызова, даже если текущий провалился.

- **Быстрая корректировка цен: `adjustPercent` может быть 0 из-за `numberInput(..., 0)`** — строка 579: `onChange={(event) => setAdjustPercent(numberInput(event.target.value, 0))}`. Fallback равен `0`, поэтому при вводе нечислового значения percent становится 0. Кнопка «Применить» задизейблена при `!(adjustPercent > 0)` — защита есть, но состояние поля визуально показывает `0`, что путает.

- **`useEffect` для синхронизации `rules` из сервера слишком ограничен** — строка 305–307: `if (rulesQuery.data?.priceRules !== undefined && !rules) setRules(rulesQuery.data)`. Условие `!rules` означает, что если пользователь изменил правила вручную, а затем внешнее сохранение обновило `rulesQuery.data`, локальное состояние не обновится. Но если страница перезагружается (navigate away / back), `rules` сбросится в `null` и возьмёт свежие данные — поведение непоследовательное.

- **`previewData.skippedSample` показывает только первую причину** — строка 850: `reasonLabel(item.reasons[0] || "unknown")`. У товара может быть несколько причин пропуска, но UI показывает только первую.

## Improvement Ideas

- **[HIGH]** Добавить confirm-диалог при удалении объявления из фида (кнопка Trash2) — с указанием названия объявления.

- **[HIGH]** Вынести `apiJson` из файла, использовать общую из `../api` — устранит дублирование и обеспечит единообразную обработку ошибок (включая Zod-валидацию при необходимости).

- **[HIGH]** Добавить пагинацию или виртуальный скролл для списка объявлений — сейчас 200 строк рендерятся в DOM без виртуализации, что создаёт заметный lag при прокрутке на медленных машинах.

- **[MEDIUM]** Показывать все причины пропуска в предпросмотре, а не только первую — `item.reasons.map(reasonLabel).join(", ")`.

- **[MEDIUM]** Добавить текст «Синхронизируется...» на кнопку при `feedRefreshRunning` (когда `syncNow` ещё не запущен, но фоновая задача работает).

- **[MEDIUM]** Добавить `mutation.reset()` перед повторным вызовом `triggerUpload` / `syncNow`, чтобы старые сообщения об успехе не зависали на экране.

- **[MEDIUM]** Добавить возможность просмотра полного описания объявления в фиде прямо на странице (tooltip или expandable row) — сейчас описания не видны в таблице объявлений.

- **[LOW]** Показывать `lastSyncedAt` в строке объявления — поле уже есть в типе `Listing` (строка 98), но нигде не отображается.

- **[LOW]** Кнопку «Обновить» в заголовке секции «Загрузки Avito» (строка 720) привязать к `uploadsQuery.isFetching` для спиннера — сейчас кнопка не показывает загрузку.
