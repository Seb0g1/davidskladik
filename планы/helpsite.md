# SupportChatsPage — Plan

## Current State

Страница «Поддержка сайта» — двухколоночный интерфейс чатов с покупателями magicvibes.ru. Слева список чатов с фильтрами (открытые/закрытые/все), справа тред выбранного чата с историей сообщений и формой ответа. Автообновление: список каждые 8 сек, тред каждые 5 сек. Поддерживает мобильный режим (переключение list/thread).

## Bugs / Issues Found

- **`replyMutation` не сбрасывает ошибку при повторной отправке** — строки 63–74: `useMutation` сохраняет `replyMutation.error` до следующего `mutate()`. Если первая отправка провалилась с ошибкой, пользователь исправил текст и отправил снова — старая ошибка остаётся видна пока новый запрос не завершится. Нет `replyMutation.reset()` в `onSuccess` или перед `mutate()`.

- **Ошибки `replyMutation` и `statusMutation` нигде не отображаются** — в JSX нет `{replyMutation.error && ...}` и `{statusMutation.error && ...}`. Если ответ не отправится (например, чат закрылся параллельно другим пользователем и вернулся 409), пользователь не увидит причину — форма просто перестанет работать.

- **`handleSend` принимает `React.FormEvent`, но вызывается из `onKeyDown` textarea** — строка 92: `function handleSend(e: React.FormEvent)`. В `onKeyDown` (строка 244) вызывается `handleSend(e)` где `e` — `React.KeyboardEvent`. TypeScript не ловит это как ошибку, потому что `KeyboardEvent extends SyntheticEvent`, но `e.preventDefault()` вызывается на keyboard event вместо form event — семантически корректно, но путает типизацию.

- **Polling треда активен даже когда чат закрыт** — строки 56–61: `refetchInterval: 5000` всегда, независимо от `chat?.status`. Для закрытых чатов новых сообщений не появится, но запросы к `/api/support/chats/:id` продолжают отправляться каждые 5 секунд.

- **`unreadCount` считается только по статусу `"open"`** — строка 90: `chats.filter((c) => c.unreadAdmin && c.status === "open").length`. Если выбран фильтр `"closed"` или `"all"`, `chats` содержит все чаты текущего фильтра. `unreadCount` будет 0 при фильтре `"closed"` (даже если там есть непрочитанные), потому что `c.status === "open"` всегда `false`. Заголовок страницы покажет «Обращения покупателей» вместо числа — что не является багом в строгом смысле, но может быть неожиданным.

- **`detailQuery` не инвалидируется при смене `statusFilter`** — когда пользователь переключает фильтр, `selectedId` сбрасывается визуально только при явном клике на другой чат. Если `selectedId` остаётся тем же (чат есть в обоих фильтрах), правая колонка покажет старый детальный кэш пока polling не обновит его.

- **`renderChatItem` определена как внутренняя функция компонента** — строки 98–130: функция пересоздаётся при каждом рендере. Не является багом, но при большом количестве чатов (≤200, строка 120 бэкенда) может вызывать лишние перерисовки. Нет `useCallback`.

- **Бэкенд: `/api/support/chats` не валидирует `status`** — строка 114–116 бэкенда: `const status = cleanText(request.query.status || "open")`. Любое значение кроме "open"/"closed"/"all" передаётся в `where: { status }`, что породит Prisma-запрос с произвольной строкой. Хотя такое значение вернёт пустой список (а не ошибку), это потенциально нежелательное поведение.

## Improvement Ideas

- **[HIGH]** Показывать ошибки `replyMutation` и `statusMutation` — добавить блоки в JSX под формой и кнопкой статуса.

- **[HIGH]** Добавить бэкенд-валидацию `status` параметра — разрешить только `"open" | "closed" | "all"`, возвращать 400 для других значений.

- **[MEDIUM]** Остановить polling треда для закрытых чатов: `refetchInterval: chat?.status === "open" ? 5000 : 0`.

- **[MEDIUM]** Добавить `replyMutation.reset()` в `handleSend` перед вызовом `mutate`, или в `onError` коллбэке — чтобы старая ошибка не залипала.

- **[MEDIUM]** Вынести `renderChatItem` как отдельный мемоизированный компонент `<ChatItem>` — для читаемости и производительности.

- **[LOW]** Добавить автоскролл вниз при открытии треда и при получении новых сообщений — сейчас `chat-messages` не скроллится автоматически к последнему сообщению.

- **[LOW]** Добавить счётчик непрочитанных в заголовке `<PageHeader>` как badge рядом с заголовком «Поддержка сайта», а не только в `subtitle` — чтобы он был виден в навигации.

- **[LOW]** Добавить отображение даты создания и категории чата более заметно в шапке треда — сейчас `category` только мелким текстом.
